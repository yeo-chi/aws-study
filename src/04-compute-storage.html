6.1 EC2 인스턴스 유형

인스턴스 이름 m7g.2xlarge 해석: m(패밀리: 범용) 7(세대) g(속성: Graviton ARM) .2xlarge(크기: 8 vCPU, 32 GiB).

패밀리용도특징 / 예시
T버스트 범용CPU 크레딧 기반. 평소 낮고 가끔 튀는 워크로드(개발 서버). unlimited 모드 주의
M범용vCPU:메모리 = 1:4. 웹/앱 서버 기본 선택
C컴퓨팅 최적화1:2. 배치, 인코딩, 고성능 웹
R / X / z메모리 최적화1:8 이상. 인메모리 DB, 캐시, 대규모 분석
I / D / Im스토리지 최적화로컬 NVMe 고IOPS. NoSQL, 데이터 웨어하우스
P / G / Trn / Inf가속 컴퓨팅GPU(ML 학습·추론, 그래픽), Trainium·Inferentia(AWS 자체 ML 칩)

속성 접미사: g=Graviton, a=AMD, i=Intel, d=로컬 NVMe, n=네트워크 강화, e=추가 메모리/스토리지, flex=저비용 유연형. Graviton은 같은 성능 대비 x86보다 보통 20% 안팎 저렴해 우선 검토할 가치가 있습니다.

Nitro 시스템과 네트워크 성능

최신 인스턴스는 Nitro(네트워크·스토리지·보안을 전용 하드웨어로 오프로드한 하이퍼바이저)에서 동작합니다. 네트워크 성능은 인스턴스 크기에 비례하며, "Up to 12.5 Gbps"처럼 표시된 것은 버스트 성능(기준 대역폭은 더 낮음)입니다. ENA(Enhanced Networking)는 최신 AMI에서 기본 활성화됩니다.

  • 단일 흐름(5-tuple) 대역폭은 같은 배치 그룹 밖에서는 5 Gbps, 클러스터 배치 그룹 안에서는 10 Gbps(일부 최대 25 Gbps)로 제한됩니다.
  • MTU: VPC 내부 9001(점보 프레임), IGW·VPN·피어링(리전 간) 경유 시 1500(VPN은 더 작음). Path MTU Discovery를 위해 ICMP Type 3 Code 4 허용 고려.

6.3 AMI와 부트스트랩

  • AMI: 루트 볼륨 스냅샷 + 메타데이터. 리전 단위 → 다른 리전에서 쓰려면 복사.
  • 골든 AMI: 공통 에이전트·보안 설정을 미리 굽기(EC2 Image Builder, Packer). 부팅 시간 단축.
  • User Data: 최초 부팅 시 root로 실행되는 스크립트(cloud-init). 최대 16 KB.
  • Launch Template: AMI, 유형, SG, 역할, User Data 등을 버전 관리. Auto Scaling에 필수(Launch Configuration은 지원 종료).

  • 인스턴스 스토어: 호스트에 물리적으로 붙은 NVMe. 매우 빠르지만 정지/종료 시 데이터 소실(재부팅은 유지). 캐시·임시 데이터용.

6.6 Auto Scaling

Auto Scaling 그룹(ASG)은 최소/원하는/최대 용량 사이에서 인스턴스 수를 유지·조정하고, 비정상 인스턴스를 자동 교체합니다. 여러 AZ의 서브넷을 지정하면 AZ 간 균형을 맞춥니다.

조정 정책설명
대상 추적 (권장)"평균 CPU 50% 유지", "대상당 ALB 요청 1000" 같은 목표값 유지. 온도조절기처럼 동작
단계 조정CloudWatch 경보 구간별로 +1, +3 등 다르게 조정
예약 조정매일 09:00 최소 10대처럼 시간 기반
예측 조정과거 패턴을 ML로 학습해 미리 확장
  • 헬스 체크 유형: 기본은 EC2 상태 검사. ALB 뒤에 있다면 ELB 헬스 체크를 켜야 앱 장애도 교체됩니다.
  • Warm-up / 쿨다운: 새 인스턴스가 지표에 반영되기 전 과도한 확장 방지.
  • 수명 주기 후크: 시작/종료 직전에 대기(로그 수집, 등록 작업).
  • Instance Refresh: 새 Launch Template 버전으로 롤링 교체. Warm Pool: 미리 초기화된 인스턴스 대기.

핵심 기능

  • 버전 관리: 덮어쓰기·삭제로부터 보호(삭제 시 삭제 마커). 복제·Object Lock의 전제 조건.
  • 수명 주기 규칙: 30일 후 IA, 90일 후 Glacier, 365일 후 삭제, 이전 버전 정리, 미완료 멀티파트 업로드 삭제.
  • 복제: CRR(리전 간), SRR(같은 리전). 버전 관리 필요, 기존 객체는 Batch Replication.
  • Object Lock: WORM. Compliance 모드는 루트도 삭제 불가 → 랜섬웨어 대비 백업.
  • 암호화: 모든 신규 객체는 기본 SSE-S3 암호화. 키 관리·감사가 필요하면 SSE-KMS(+ 버킷 키로 KMS 비용 절감), DSSE-KMS(이중 암호화), SSE-C(고객 키).
  • 성능: 접두사당 초당 3,500 PUT / 5,500 GET. 접두사를 나누면 선형 확장. 원거리 업로드는 Transfer Acceleration.
  • 이벤트 알림: 객체 생성 시 Lambda/SQS/SNS/EventBridge 호출.
  • Presigned URL: 일정 시간만 유효한 임시 업로드/다운로드 URL.

S3 접근 제어 — 어떻게 막고 어떻게 열까

  1. 퍼블릭 액세스 차단(Block Public Access): 계정·버킷 수준. 기본 켜짐. 정말 공개가 필요한 경우가 아니면 끄지 마세요.
  2. Object Ownership = Bucket owner enforced: ACL 비활성화(기본값). 정책만으로 관리.
  3. 버킷 정책: 크로스 계정, VPC 엔드포인트 제한, TLS 강제(aws:SecureTransport).
  4. 정적 웹 호스팅은 버킷을 직접 공개하기보다 CloudFront + OAC(Origin Access Control)로 버킷은 비공개 유지.
  5. Access Points: 대규모 공유 데이터셋에 팀별 접근 정책 분리.

9.1 Amazon RDS

관리형 관계형 DB: MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2. AWS가 프로비저닝·패치·백업·장애 조치를 담당합니다(OS 접근 불가, RDS Custom 예외).

구분Multi-AZ (인스턴스 배포)Multi-AZ DB 클러스터읽기 전용 복제본
목적고가용성고가용성 + 읽기읽기 확장
복제동기반동기, 리더 2개비동기
읽기 가능?스탠바이는 읽기 불가리더 2개 읽기 가능가능(별도 엔드포인트)
장애 조치자동(보통 60~120초), DNS 엔드포인트 동일자동(보통 35초 이내)수동 승격

  • 수동 스냅샷은 삭제 전까지 보존. 다른 리전/계정에 복사 가능.
  • RDS Proxy: 커넥션 풀링으로 Lambda의 대량 연결 문제 해결, 장애 조치 시간 단축, IAM 인증.
  • DB 서브넷 그룹: 최소 2개 AZ의 프라이빗 서브넷. 퍼블릭 액세스는 "아니요".
  • 암호화는 생성 시에만 설정 가능 → 미암호화 DB는 스냅샷 → 암호화 복사 → 복원.

9.2 Amazon Aurora

MySQL/PostgreSQL 호환 클라우드 네이티브 DB. 컴퓨팅과 스토리지가 분리되어 있고, 스토리지는 3개 AZ에 6개 사본으로 자동 복제(쓰기 4/6, 읽기 3/6 쿼럼)됩니다.

  • 복제본 최대 15개, 복제 지연 대개 수십 ms. 라이터 엔드포인트 / 리더 엔드포인트(부하 분산) / 사용자 지정 엔드포인트.
  • 스토리지 자동 확장(최대 128 TiB 이상, 엔진 버전에 따라 상이).
  • Aurora Serverless v2: ACU 단위로 초 단위 자동 확장(0 ACU까지 일시 중지 지원).
  • Global Database: 다른 리전에 1초 미만 지연 복제, 리전 장애 시 1분 내외 승격 → 리전 DR.
  • Backtrack(MySQL): 스냅샷 복원 없이 시점 되돌리기. 클론: 카피 온 라이트로 빠른 복제.
  • Aurora DSQL: 분산 SQL, 멀티 리전 액티브-액티브(2025 정식 출시).

9.3 Amazon DynamoDB

완전 관리형 키-값/문서 NoSQL. 한 자릿수 ms 지연을 어떤 규모에서도 유지합니다. 서버 개념이 없습니다.

개념설명
기본 키파티션 키(PK) 단독 또는 PK + 정렬 키(SK). PK는 카디널리티가 높게(핫 파티션 방지)
항목 크기최대 400 KB
보조 인덱스GSI(다른 PK/SK, 언제든 추가), LSI(같은 PK 다른 SK, 테이블 생성 시에만)
용량 모드온디맨드(요청당 과금, 예측 불가 트래픽) / 프로비저닝(RCU·WCU + Auto Scaling, 예측 가능 트래픽에 저렴)
일관성기본 최종 일관 읽기, 강력한 일관 읽기 선택 가능(2배 RCU)
부가 기능Streams(변경 이벤트 → Lambda), TTL(자동 만료), PITR, Global Tables(멀티 리전 액티브-액티브), 트랜잭션, DAX(마이크로초 캐시)
💡 DynamoDB 설계의 핵심RDB처럼 "엔터티별 테이블 + 조인"이 아니라 접근 패턴을 먼저 정의하고 그에 맞게 키를 설계합니다(Single-table design). Scan은 비싸고 느리므로 Query로 해결되도록 설계하세요.
