CHAPTER 10DNS와 콘텐츠 전송

10.1 Route 53

고가용성 DNS 서비스(SLA 100%), 도메인 등록, 헬스 체크를 제공합니다.

  • 퍼블릭 호스팅 영역: 인터넷에서 조회. 프라이빗 호스팅 영역: 연결된 VPC 안에서만 조회(Split-horizon DNS 가능).
  • 도메인을 다른 등록 기관에서 샀다면, 그곳의 NS 레코드를 Route 53 호스팅 영역의 4개 네임서버로 바꿔야 합니다.
  • TTL: 변경 전에 미리 TTL을 낮춰 두면 전환이 빨라집니다. Alias 레코드는 대상 리소스의 TTL을 따릅니다.

라우팅 정책 [SAA 빈출]

정책동작용도
단순(Simple)하나의 레코드(여러 IP면 무작위 순서). 헬스 체크 불가단일 리소스

헬스 체크: 엔드포인트(HTTP/HTTPS/TCP), 다른 헬스 체크 조합(계산된), CloudWatch 경보 기반. 헬스 체커는 인터넷에서 접근하므로 프라이빗 리소스는 CloudWatch 경보 방식을 사용합니다. 방화벽에서 Route 53 헬스 체커 IP 대역을 허용해야 합니다.

10.2 CloudFront

전 세계 수백 개 엣지 로케이션에서 콘텐츠를 캐시하는 CDN입니다. 정적 파일뿐 아니라 동적 콘텐츠(API)도 AWS 백본을 통한 최적 경로·TLS 종료·연결 재사용으로 빨라집니다.

개념설명
오리진S3, ALB, EC2, API Gateway, 임의 HTTP 서버, 그리고 VPC 오리진(프라이빗 서브넷의 ALB/NLB/EC2를 퍼블릭 노출 없이)
캐시 동작(Behavior)경로 패턴별 오리진·캐시 정책 지정 (/api/*는 캐시 안 함, /static/*는 1일 캐시)
캐시 정책 / 오리진 요청 정책캐시 키(헤더·쿠키·쿼리) vs 오리진으로 전달할 값 분리. 캐시 키가 많을수록 적중률↓
OACS3 오리진을 CloudFront만 접근 가능하게(버킷 정책에서 CloudFront 서비스 주체 + 배포 ARN 조건)
ALB 오리진 보호ALB SG에 CloudFront 관리형 프리픽스 리스트만 허용 + 커스텀 헤더 검증, 또는 VPC 오리진
무효화(Invalidation)캐시 강제 삭제(비용 발생) → 파일명 버전 관리(app.3f2a.js)가 더 좋음
서명된 URL/쿠키유료 콘텐츠 접근 제한
엣지 컴퓨팅CloudFront Functions(경량 JS, 헤더 조작·리다이렉트), Lambda@Edge(무거운 로직)
보안WAF 연결, Shield Standard 기본, 지리적 제한, TLS 인증서는 us-east-1의 ACM에서 발급

14.2 CloudFormation 예제: VPC + 퍼블릭 서브넷

AWSTemplateFormatVersion: "2010-09-09"
Parameters:
  VpcCidr: { Type: String, Default: 10.0.0.0/16 }
Resources:
  Vpc:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: !Ref VpcCidr
      EnableDnsSupport: true
      EnableDnsHostnames: true
      Tags: [{ Key: Name, Value: study-vpc }]
  Igw: { Type: AWS::EC2::InternetGateway }
  IgwAttach:
    Type: AWS::EC2::VPCGatewayAttachment
    Properties: { VpcId: !Ref Vpc, InternetGatewayId: !Ref Igw }
  PublicSubnetA:
    Type: AWS::EC2::Subnet
    Properties:
      VpcId: !Ref Vpc
      CidrBlock: !Select [0, !Cidr [!Ref VpcCidr, 6, 8]]   # 10.0.0.0/24
      AvailabilityZone: !Select [0, !GetAZs ""]
      MapPublicIpOnLaunch: true
  PublicRt: { Type: AWS::EC2::RouteTable, Properties: { VpcId: !Ref Vpc } }
  DefaultRoute:
    Type: AWS::EC2::Route
    DependsOn: IgwAttach
    Properties: { RouteTableId: !Ref PublicRt, DestinationCidrBlock: 0.0.0.0/0, GatewayId: !Ref Igw }
  PublicAssocA:
    Type: AWS::EC2::SubnetRouteTableAssociation
    Properties: { SubnetId: !Ref PublicSubnetA, RouteTableId: !Ref PublicRt }
Outputs:
  VpcId: { Value: !Ref Vpc, Export: { Name: study-vpc-id } }
aws cloudformation deploy --template-file vpc.yaml --stack-name study-vpc
aws cloudformation delete-stack --stack-name study-vpc

CHAPTER 15고가용성·재해 복구·비용 최적화

학습 목표 · RTO/RPO로 요구사항을 수치화한다 · DR 전략 4가지를 비용·복구 시간으로 비교한다 · 비용 구조(특히 데이터 전송)를 이해하고 줄인다

15.1 고가용성 설계 원칙

  • 단일 장애점(SPOF) 제거: 모든 계층을 최소 2개 AZ에. NAT GW도 AZ별로.
  • 상태 비저장(Stateless) 앱: 세션·파일을 인스턴스 밖(ElastiCache, DynamoDB, S3, EFS)으로 → 자유로운 확장·교체.
  • 느슨한 결합: 큐로 계층 분리 → 한 계층 장애가 전체로 번지지 않음.
  • 자동 복구: ASG + ELB 헬스 체크, RDS Multi-AZ, Route 53 장애 조치.
  • 재시도 + 지수 백오프 + 지터, 타임아웃, 서킷 브레이커.
  • 정적 안정성(Static Stability): 장애 시 새 자원을 만들지 않아도 버틸 만큼 미리 확보(예: 3 AZ에 각 50% 용량 → 1 AZ 손실 시에도 100%).

15.2 RTO / RPO

RPO(Recovery Point Objective): 얼마만큼의 데이터 손실을 허용하는가(시간). RTO(Recovery Time Objective): 서비스가 복구되기까지 허용 시간.

DR 전략방식RPO/RTO비용

웜 스탠바이축소된 규모의 전체 환경이 상시 동작, 장애 시 확장 + DNS 전환초~분 / 분$$$
멀티 사이트 액티브-액티브여러 리전이 동시에 트래픽 처리(Aurora Global, DynamoDB Global Tables, Route 53 지연/가중치)거의 0 / 거의 0$$$$

AWS Elastic Disaster Recovery(DRS)는 서버 블록 수준 지속 복제로 온프레미스/타 리전 서버의 DR을 저비용으로 구성합니다. DR 훈련을 정기적으로 하지 않은 DR 계획은 동작하지 않는다고 가정하세요. AWS Fault Injection Service로 장애를 주입해 검증할 수 있습니다.

  1. 가시화: 비용 할당 태그, Cost Explorer, Budgets, Cost Anomaly Detection, CUR(상세 보고서).
  2. Right-sizing: Compute Optimizer 권고 반영, 과대 인스턴스 축소.

  9. 서버리스·관리형으로 유휴 비용 제거.
  10. 로그 보존 기간 설정(CloudWatch Logs 무기한 보존 방지).
